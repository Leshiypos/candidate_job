# Тестовое задание: аванс по договору

Около 2-3 часов. Работа - в Claude Code.

## Контекст

Компания заказывает работы у подрядчиков: съёмки, дизайн. Договор с подрядчиком - это общая сумма на несколько работ. Платим по договору авансом и остатками, иногда платёж привязан к конкретной работе.

Письмо бухгалтера:

> Мне нужен отчёт: по каждой работе - сколько уже выплачено и сколько осталось оплатить, и итог по каждому договору. Сейчас считаю в таблице руками и путаюсь: платежи по договору ни к какой работе не привязаны, а мне надо понимать, за что мы уже рассчитались. Отчёт нужен на дату, для проверки - на 10.11.2026.

## Что есть

Папка `data/`: договоры, работы, платежи и описание формата в `FORMAT.md`.

Бухгалтер в отпуске и на связи не будет, других источников, кроме `data/`, нет. Где данных не хватает, решите сами и запишите допущение в `DECISIONS.md`.

## Что сдать

1. **Программа** на Python или TypeScript - скрипт, CLI или маленький HTTP-сервис, на ваш выбор. По файлам из `data/` и дате она строит отчёт:
   - по каждой работе: цена, выплачено, осталось оплатить;
   - по каждому договору: итоги.

   Напишите, как её запустить: мы запустим сами.

2. **Файл `DECISIONS.md`** - решения, которые вы приняли по ходу работы. По каждому решению коротко:
   - что решали;
   - какие были варианты;
   - что выбрали и почему;
   - что изменится в отчёте, если выбор окажется неверным.

   Пример оформления на постороннюю тему:

   > **Формат отчёта.** Варианты: таблица в консоли или файл CSV. Выбрал CSV: его можно открыть в таблице. Если неверно, поменяется только вывод, расчёт останется прежним.

3. **Записка бухгалтеру** на 5-10 строк простым языком: как читать отчёт и что ей нужно подтвердить, когда вернётся.

4. **Полный транскрипт работы с Claude Code** - экспорт командой `/export`, без правок. Если сессий было несколько - все. Ключи и пароли, если попали в сессию, можно вырезать.

Интерфейс, база данных и docker не нужны. Деньги считайте точно, до копейки, без float.

Не успели всё - напишите, что осталось и что бы вы сделали дальше.

## Как сдать

Ссылкой на приватный репозиторий или архивом - туда, откуда получили задание. Задание, данные и решение не публикуйте.

## Запуск

Распакуйте проект, если получили его архивом. Откройте терминал в папке,
где находятся этот README и каталог `advance_report/`. Для запуска нужен
Python 3.11 со стандартной библиотекой. Проверьте версию командой
`python --version`. Если у вас интерпретатор запускается как `python3`,
используйте `python3` в командах ниже.

Постройте отчёт на контрольную дату.

```powershell
python -m advance_report --data-dir data --date 2026-11-10 --output-dir output
```

Все три аргумента обязательны.

| Аргумент | Что указать |
| --- | --- |
| `--data-dir` | Папка с `contracts.csv`, `works.csv` и `payments.csv`. Заголовки, поля и форматы описаны в [схеме CSV](data/FORMAT.md). |
| `--date` | Дата в формате `YYYY-MM-DD`. Отчёт включает события до конца этого дня. |
| `--output-dir` | Папка для результата. Программа создаст её при необходимости. |

Программа напечатает путь к `output/report-2026-11-10.md`. Откройте файл
в Markdown-просмотрщике с поддержкой таблиц или как текст UTF-8. В PowerShell
его можно прочитать командой `Get-Content -Encoding UTF8 output/report-2026-11-10.md`.
Успешный повторный запуск за ту же дату в ту же папку заменит этот файл.

Код завершения `0` означает успешный запуск. При ошибке программа выводит
диагностику в поток ошибок и возвращает `1` для чтения, проверки CSV или
записи отчёта и `2` для неверных аргументов. Если ошибка относится к
конкретной строке CSV, диагностика указывает файл, строку и поле.

## Как строится отчёт

1. Загрузчик читает три CSV, проверяет поля, идентификаторы, связи между
   строками, суммы и даты. Расчёт использует целые копейки.
2. В отчёт попадают договоры, подписанные к концу указанного дня.
   Даты приёмки и отмены определяют статус работ. Платёж учитывается
   с даты оплаты и исключается с даты полного возврата.
3. Прямые платежи засчитываются указанным работам. Общие выплаты по
   договору распределяются между работами пропорционально их ценам,
   ещё не покрытым прямыми платежами. Сумма распределения ограничена
   непокрытыми ценами, а избыток показан в договоре отдельной строкой.
4. Программа записывает Markdown-отчёт с таблицей итогов каждого договора
   и строками его работ. Выплата по работе включает прямые выплаты и
   условную долю общих выплат. Остаток договора рассчитывается от полной
   суммы договора, а остаток работы — от её расчётной цены.

У отменённой работы расчётная цена равна нулю. Для запланированной работы
остаток показывает непокрытую цену, а срок оплаты уточняется по договору.
Подробные расчётные правила и порядок распределения остаточных копеек
описаны в [DECISIONS.md](DECISIONS.md). Пояснения к таблицам и вопросы для
сверки собраны в [записке бухгалтеру](ACCOUNTANT_NOTE.md).
