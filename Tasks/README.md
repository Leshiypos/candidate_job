# Поэтапная работа

В проекте есть исходное задание, три CSV и рабочий Python CLI с тестами. Подготовлены контрольный отчёт и записка бухгалтеру.

Перед выбором задачи используйте [Roadmap.md](../Roadmap.md): там указаны общая цель, текущий этап и ограничения.

## Реестр

| Этап | Задача | Статус | Зависит от |
| --- | --- | --- | --- |
| 000 | [Подготовка документации](000-project-setup.md) | done | — |
| 001 | [Правила расчёта](001-calculation-rules.md) | done | — |
| 002 | [Чтение и проверка данных](002-input-validation.md) | done | 001 |
| 003 | [Расчёт на дату](003-calculation.md) | done | 002 |
| 004 | [CLI, отчёт и записка](004-report-cli.md) | done | 003 |
| 005 | [Проверка и подготовка сдачи](005-delivery.md) | todo | 004 |

Статусы: `todo`, `in_progress`, `blocked`, `done`. Статусы в реестре, файле задачи и Roadmap.md должны совпадать. После каждого выполненного задания обязательны проверки и запись результатов; до их успешного завершения `done` ставить нельзя.

## Предлагаемая структура

Следующие пути — план, а не утверждение, что все файлы уже существуют.

```text
README.md                 исходное условие; позже — проверенная инструкция запуска
AGENTS.md                 правила для работающих в проекте агентов
Roadmap.md                используемая карта этапов, прогресса и ограничений
DECISIONS.md              решения и последствия ошибочных допущений
ACCOUNTANT_NOTE.md        записка бухгалтеру, создаётся на этапе 004
data/                     неизменяемые исходные CSV и FORMAT.md
Tasks/                    задачи, критерии приёмки, результаты проверок
docs/DELIVERY.md          состав сдачи и проверка секретов
advance_report/
  __init__.py
  __main__.py             CLI: аргументы, запуск, коды завершения
  models.py               типы договоров, работ, платежей и результатов
  input.py                чтение CSV и проверка входных данных
  calculation.py          состояние на дату и распределение денег
  output.py               вывод отчёта
tests/                    unittest, синтетические примеры и проверки исходных CSV
output/                   локальные отчёты, исключены из Git
private/                  непроверенные экспорты сессий, исключены из Git
dist/                     проверенный комплект сдачи, исключён из Git
```

Проверенная команда: `python -m advance_report --data-dir data --date 2026-11-10 --output-dir output`. Инструкция запуска находится в [README.md](../README.md).

## Порядок ведения документации

1. Взять следующую задачу с выполненными зависимостями.
2. Зафиксировать принятые решения в `DECISIONS.md`, сослаться на их номера в задаче.
3. Реализовать только нужный текущему этапу объём и связанные тесты.
4. Запустить проверки этапа и имеющиеся регрессионные тесты. Для Python-кода дополнительно проверить стиль, читаемость, повторяющуюся логику и необходимые комментарии по AGENTS.md, записать результат обзора в задаче. Для этапа без кода провести документированные проверки документации.
5. В разделе «Результат и проверки» записать изменения, команды или процедуру, фактический результат и оставшиеся ограничения.
6. После успешной приёмки обновить статусы в задаче, реестре и Roadmap.md, а также текущее состояние и следующий этап в дорожной карте. Новые задачи создавать по [шаблону](TEMPLATE.md) и добавлять в реестр и дорожную карту.
7. После каждой выполненной задачи создать отдельный локальный коммит по правилам [AGENTS.md](../AGENTS.md), включая результаты проверок и связанную документацию. Сообщить пользователю хеш; если коммит невозможен, явно указать причину. Не выполнять push без отдельного поручения.

Результаты расчёта не дублировать в задачах как отдельные источники истины: ожидаемые суммы закрепляются в проверках, правила — в журнале решений.
