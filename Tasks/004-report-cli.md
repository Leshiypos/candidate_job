# 004. CLI, отчёт и записка бухгалтеру

Статус: done
Зависимости: 003.

## Цель

Дать воспроизводимый способ получить и понять отчёт.

## Работа

- Реализовать аргументы каталога данных, даты и каталога результата, справку и коды завершения.
- Вывести по каждой работе цену, выплачено и остаток; по каждому договору — итоги и необходимые пояснения к распределению.
- При выборе CSV обеспечить корректные кавычки и безопасный вывод текстовых полей, которые табличные редакторы могут трактовать как формулы.
- Добавить в README проверенную инструкцию запуска и тестов, сохранив текст задания.
- Создать `ACCOUNTANT_NOTE.md`: 5–10 строк простым языком с объяснением отчёта и вопросами для подтверждения.

## Критерии приёмки

- [x] Команды из README работают в описанном окружении без секретов и сети.
- [x] Отчёт явно содержит дату и различает фактические выплаты и расчётное распределение.
- [x] Ошибочный ввод даёт понятное сообщение и ненулевой код завершения.
- [x] Записка соответствует принятой методике и не выдаёт допущения за факты.
- [x] После задания пройдены тесты CLI, вывода и весь существующий набор.
- [x] Документы, отчёты и изменённые файлы проверены на секреты.

## Проверки после задания

Автоматически проверить успешный запуск во временный каталог, `--help`, неверную дату, отсутствующий входной файл, формат денежных полей, итоги отчёта и текст с кириллицей/кавычками. Если выбран CSV, проверить потенциальные формулы в текстовых полях. Убедиться, что исходные CSV не изменены.

Запустить `python3 -m unittest discover -s tests -v` и фактическую команду из README для 2026-11-10. Открыть результат как текст, сверить суммы, вручную проверить записку и ссылки документации.

## Результат и проверки

Реализованы CLI, отчёт UTF-8 Markdown и [записка бухгалтеру](../ACCOUNTANT_NOTE.md) из семи пунктов. Общий парсер даты используется для проверки CSV и аргумента CLI. Отчёт заменяется после успешной записи временного файла. Для форматирования таблиц нужен Markdown-просмотрщик с их поддержкой, содержимое читается и как текст UTF-8.

- `python --version` показал 3.11.9. `python -m advance_report --help` и `python -m advance_report --data-dir data --date 2026-11-10 --output-dir output` выполнены успешно. Просмотрен `output/report-2026-11-10.md`. Суммы и статусы девяти работ и итоги двух договоров сверены с эталоном 001. Отчёт различает чистые фактические выплаты и условные доли.
- `python -m unittest discover -s tests -v`: 44 теста прошли, включая девять новых. Проверены справка, неверная дата, отсутствующий входной файл, ошибка записи, повторная генерация, формат денег и знаковой разницы, кириллица, кавычки, экранирование Markdown-разметки и управляющих символов. Временный файл удаляется и при ошибке замены.
- Дополнительная проверка через `python -X utf8 -B -` вызвала CLI на 2026-08-24 и 2026-11-12. В первом отчёте нет подписанных договоров, во втором W-23 принята и учтён P-8. Сумма выплат D-2 составила 95000.00, переплата и нераспределённые выплаты составили по 5000.00.
- Ручной обзор подтвердил читаемость функций, имена, типизацию, docstring, переиспользование проверки даты и пояснения к экранированию и записи. Встроенная проверка AST и текста подтвердила аннотации, отсутствие литералов `float` и строки до 79 символов. Просмотрена записка и проверено, что исходный README сохранился побайтно перед новым разделом.
- Проверены ссылки, статусы, `git diff --check`, `git diff --exit-code HEAD -- data` и исключение отчёта из Git. Поиск по шаблонам ключей, токенов, паролей, заголовков авторизации и URL с учётными данными в отчёте и изменённых файлах совпадений не обнаружил.

### Дополнение к инструкции запуска

В [README](../README.md) описаны обязательные аргументы, открытие результата в PowerShell, коды завершения, порядок расчёта и контрольные итоги по двум договорам.

- На Python 3.11.9 проверены `python -m advance_report --help` и два запуска `python -m advance_report --data-dir data --date 2026-11-10 --output-dir output`. Отчёт содержит две секции договоров и девять строк работ. Итоги совпали с ручной сверкой этапа 001, а оба файла отчёта побайтно совпали с контрольным образцом. Команда `Get-Content -Encoding UTF8 output/report-2026-11-10.md` прочитала результат.
- Отдельные вызовы CLI проверили коды `1` при отсутствующем входном файле и при попытке записать отчёт в путь, занятый файлом, и код `2` при дате вне формата `YYYY-MM-DD`. `python -m unittest discover -s tests -v` выполнила все 44 теста успешно.
- Сверены исходный текст задания, локальные ссылки, статусы и вывод `git diff --check`. `git diff --exit-code HEAD -- advance_report data tests` подтвердил отсутствие изменений программы, исходных CSV и тестов. Поиск по шаблонам секретов в изменённых документах совпадений не обнаружил.
