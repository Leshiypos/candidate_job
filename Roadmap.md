# Дорожная карта проекта

Рабочий документ для выбора следующего этапа и контроля готовности. Обновлять при изменении этапов, их статусов, зависимостей или ограничений.

## Цель

Создать локальный Python CLI, который по исходным CSV и заданной дате показывает цену, выплаченную сумму и остаток по каждой работе, а также итоги по договорам. Контрольная дата — 2026-11-10. Деньги рассчитываются точно до копейки, без float.

## Текущее состояние

Расчёт на дату принят и сверён с ручным эталоном. Следующий этап — **004, CLI, отчёт и записка бухгалтеру**.

Этапы реализации выполняются последовательно: 001 → 002 → 003 → 004 → 005. Подробные зависимости и критерии приёмки находятся в [реестре задач](Tasks/README.md) и файлах этапов.

## Как использовать документ

1. Перед началом работы прочитать эту карту и выбрать следующий этап с выполненными зависимостями.
2. Открыть файл задачи, проверить критерии приёмки и перевести её в `in_progress`. Синхронно обновить статус здесь и в реестре.
3. Принятые решения записывать в [DECISIONS.md](DECISIONS.md). Подробности реализации и результаты проверок хранить в задаче; здесь оставлять краткую картину проекта.
4. После каждого задания выполнить предусмотренные проверки. Для кода обязательны тесты поведения и существующий регрессионный набор; для документации — проверка ссылок, согласованности и отсутствия секретов.
5. Только после успешной приёмки поставить `done` в задаче, реестре и этой карте. Обновить текущее состояние и следующий этап.
6. Если работа заблокирована, явно записать причину и необходимое действие в задаче и кратко отразить ограничение здесь. Не отмечать непроверенную работу завершённой.
7. После каждой выполненной и проверенной задачи создать отдельный локальный коммит с её изменениями и документацией по правилам AGENTS.md. Если коммит невозможен, сообщить причину; публикация требует отдельного поручения.

Детальные статусы и доказательства завершения хранятся в файлах задач; сводки в реестре и дорожной карте должны им соответствовать.

## Условия готовности

- Работают команда из README и отчёт на 2026-11-10; тесты пройдены и результаты записаны.
- Расчётные допущения объяснены в DECISIONS.md, подготовлена записка бухгалтеру на 5–10 строк.
- Сдаваемые файлы и записи сессий проверены по [правилам сдачи](docs/DELIVERY.md); секреты и непроверенные материалы не включены.
- Состав подтверждающих записей ИИ-сессий соответствует условиям работодателя; оставшиеся ограничения явно указаны.

## Текущие ограничения и открытые вопросы

- Сторонний ИИ разрешён работодателем по уточнению пользователя (D-003); разработка в Codex допустима. Формат сдачи его сессий с учётом требования README об экспорте Claude Code пока не установлен.
- Поиск по шаблонам не гарантирует отсутствие любых секретов. Перед сдачей проверяется точный комплект, включая транскрипты и историю Git, если она передаётся.
